Schema version 2: SQLAlchemy metadata creates users/samples/batches/evidence/audit/withdrawals. seed_demo initializes the separate invoices fixture table (with due_date) and NOLOGIN query_reader. invoices is the only permitted SQL source. Run `python -m scripts.seed_demo` for repeatable initialization; natural keys preserve user edits.

v2 adds the `withdrawals` table (id, batch_id, invoice_id, status[pending/effective/failed], fail_reason, created_at, updated_at; unique on (batch_id, invoice_id)) for due-invoice withdrawal registrations, and a nullable `due_date DATE` column on invoices. Withdrawal filtering is applied at read time on evidence, never rewriting the archived result: once a withdrawal is effective it removes that invoice's rows globally from every evidence view/export (old archives and concurrent reviews), while equivalent/error conclusions, plans, and original row counts remain queryable. The v1→v2 seed adds `due_date` idempotently on an existing invoices table.
